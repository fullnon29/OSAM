# 오샘 서류 정리 도구 (윈도우)

내 컴퓨터의 수급자 서류 폴더를 통째로 읽어 시스템에 올립니다.
웹 브라우저로는 폴더를 통째로 읽을 수 없어 이 프로그램이 필요합니다(요구사항 11).

서류를 읽고·판별하고·수급자를 알아내는 부분은 웹앱과 **같은 코드**를 씁니다
(`src/lib/documents/`). 화면만 다를 뿐 동작과 결과는 웹과 동일합니다.

## 처음 한 번 설정

접속 열쇠를 실행파일에 넣지 않았습니다. 실행파일에 박아 배포하면 유출 시
회수할 수 없기 때문입니다. 대신 아래 위치에 설정 파일을 둡니다.

```
C:\Users\<사용자>\AppData\Roaming\osam-desktop\settings.json
```

창에 뜨는 이름은 `오샘 서류 정리 도구` 지만 폴더 이름은 `osam-desktop`
입니다. 프로그램이 제 설정 자리를 `desktop/package.json` 의 `name` 으로
잡기 때문입니다. 저장 폴더 기억(`prefs.json`)과 포털 로그인도 같은 폴더에
있습니다. `접속 설정을 찾을 수 없습니다` 가 뜨면 여기부터 보십시오.

```json
{
  "url": "https://<프로젝트>.supabase.co",
  "key": "<Supabase secret key>"
}
```

## 쓰는 법

1. **폴더 선택** — 서류가 든 폴더를 고릅니다(하위 폴더까지 모두 찾습니다)
2. **올리기 시작** — 진행률과 건수가 실시간으로 보입니다
3. 중간에 **중지**해도 되고, 다시 실행하면 이어서 진행됩니다

같은 파일은 내용을 기준으로 알아보고 건너뛰므로 **여러 번 실행해도 안전**합니다.
파일명이나 위치가 바뀌어도 같은 파일이면 중복으로 올라가지 않습니다.

수급자 연결은 **장기요양인정번호가 일치할 때만** 자동으로 합니다.
이름은 동명이인이 있어 잘못 붙으면 엉뚱한 어르신 기록이 되므로,
번호가 없는 서류는 미연결로 두고 사람이 확인하도록 남깁니다.

## RFID 전송내역을 기준표와 맞추기

포털의 **RFID → 전송내역 → 요양요원-전송내역** 화면에 뜬 급여 항목을
`시간배분` 기준표와 견주어, 다른 곳을 찾아 고칩니다.

로그인은 여기서도 선생님이 직접 하십니다. 포털 창을 띄우고 그 화면까지
들어가 두신 뒤에 쓰십시오.

### 쓰는 차례

1. **저장 폴더 선택** — 보고서와 기록이 여기 쌓입니다
2. **기준표 선택** — `시간배분(최종저장-문).xlsx`
3. **급여제공일** — 기본은 어제입니다. 어제·오늘·지난주·이번달·지난달 단추가 있고
   날짜를 직접 고르셔도 됩니다. 주·월 단위로 잡으시는 편이 낫습니다.
   목욕 횟수는 하루만 보아서는 정할 수 없기 때문입니다.
4. **1줄만 시험** — 처음 쓰실 때 한 줄만 읽어 보고 멈춥니다
5. **점검 (읽기만)** — 조회해서 줄마다 상세를 열어 읽고, 무엇이 다른지
   엑셀로 냅니다. **이 단계에서 포털에는 아무것도 쓰지 않습니다.**
6. 엑셀을 열어 확인하십시오
7. **승인하고 반영** — 그제야 실제로 고쳐 저장합니다

점검과 반영을 가른 것은 되돌리기 어렵기 때문입니다. 163분 곱하기 한 달치를
한 번에 잘못 고치면 손으로 되돌릴 수 없습니다.

### 무엇을 손대고 무엇을 손대지 않는지

기준표에 **적힌 것만** 손댑니다. 칸이 비어 있으면 켜지도 끄지도 않습니다.

| 기준표 칸 | 포털 항목 |
|---|---|
| 위생 | 세면도움 · 구강관리 · 머리감기기 · 몸단장 · 옷갈아입히기 |
| 몸씻기 | 목욕도움 (횟수는 '몸씻' 칸을 따릅니다) |
| 식사도움 | 식사도움 |
| 체위 | 체위변경 |
| 이동 | 이동도움 |
| 화장실 | 화장실이용하기 |
| 식사준비 | 취사 |
| 개인활동 | 개인활동지원 |

신체기능의유지증진 · 청소및주변정돈 · 세탁 · 일상업무대행은 기준표에 칸이
없어 손대지 않습니다. 이 이어 주는 표는 `rfid-plan.ts` 의 `ITEM_TARGETS`
한곳에 있습니다. 포털 항목 이름이 다르면 거기만 고치면 됩니다.

**손대지 않고 알려만 드리는 경우**

- 기준표에 없는 성함
- 기준표에 같은 성함이 여러 줄이고 내용이 다른 경우
- 인지활동형처럼 기준표에 항목 표시가 없는 분
- 기준표 비고에 `차량목욕` 이 적힌 분의 목욕도움
  (방문목욕으로 받으시는 분이라 방문요양 기록에 켜면 두 번 청구한 것처럼 보입니다)
- 기준보다 목욕이 **많이** 켜져 있는 경우 — 기본은 끄지 않습니다.
  요양요원이 실제로 해 드린 것을 우리가 지우는 편이 더 큰 잘못이기 때문입니다.
  끄시려면 화면의 체크를 켜십시오.

### 목욕 횟수

기준표 `몸씻` 칸을 따릅니다. `주2`·`월2`·`매일`·`필요시`·`x` 를 읽습니다.

주 단위는 그 주 안에서, 달 단위와 `필요시` 는 그 달 안에서 셈합니다.
**이미 켜져 있는 날을 먼저 셈에 넣고**, 모자란 만큼만 더 켭니다. 실제로
적힌 것을 우리가 지우고 다른 날로 옮기는 일이 없도록 하기 위해서입니다.

`필요시` 는 정해진 날이 없어 한 달에 1~2회(화면에서 바꾸실 수 있습니다)를
배정하고, 그때 비고가 비어 있으면 "어르신의 요청으로 목욕도움" 을 적습니다.
비고에 이미 적힌 글이 있으면 손대지 않습니다.

> `필요시` 배정은 실제 제공 여부가 아니라 **규칙으로 만들어 낸 것**입니다.
> 보고서 '자동생성' 칸에 따로 표시되니, 반영 전에 실제로 해 드린 날이
> 맞는지 확인해 주십시오.

같은 기간을 다시 돌리면 **같은 날이 나옵니다**(성함과 주·월로 씨앗을
정합니다). 어제 만든 보고서와 오늘 만든 보고서가 달라지면 무엇이 맞는지
알 수 없기 때문입니다.

### 보고서

`RFID점검-날짜.xlsx` · `RFID반영-날짜.xlsx` 로 나옵니다. 시트 세 장입니다.

- **작업내역** — 일시 · 급여제공일 · 어르신 · 요양요원 · 항목 · 이전 · 이후 · 사유 · 자동생성 · 반영결과
- **확인필요** — 손대지 않은 것과 그 까닭
- **요약** — 언제 · 무엇을 · 몇 건, 그때 쓴 설정

진행 내역은 `RFID점검기록-날짜.txt` 로도 한 줄씩 쌓입니다. 중간에 멎어도
어디까지 갔는지 남습니다.

### 어긋날 때

화면 구조는 개편되면 바뀝니다. **화면 살펴보기** 를 누르면 그 화면의 자료
묶음과 체크 칸 이름을 `RFID화면구조-날짜.json` 으로 뽑습니다(성함·인정번호는
빼고 뼈대만 담습니다). 우리가 아는 항목이 몇 개나 잡혔는지도 함께 알려
드리니, 0개에 가까우면 `ITEM_TARGETS` 의 이름을 그 파일에 맞춰 고치십시오.

반영할 때는 줄 번호만 믿지 않습니다. 점검한 뒤에 다시 조회하셨으면 번호가
밀리기 때문에, 성함과 급여제공일이 점검할 때와 같은지 확인하고 다르면 그
줄은 건너뜁니다. 점검 뒤에 누가 그 항목을 고쳤어도 덮어쓰지 않고 건너뜁니다.

## 개발

```bash
node desktop/build.mjs                                   # 번들
npx electron desktop/dist/main.js                        # 실행
npx electron-builder --config desktop/builder.yml --win  # 실행파일 생성
```

빌드 출력은 `C:/osam-build/release` 로 나갑니다.
바탕화면 폴더는 클라우드 동기화 대상이라 빌드 중 파일이 잠기기 때문입니다.
